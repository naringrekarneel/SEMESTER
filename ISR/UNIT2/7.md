# 7. Probabilistic Retrieval Model

## 1. Introduction

The **Probabilistic Retrieval Model** is an Information Retrieval model that ranks documents according to their **probability of being relevant to a user's query**.

The basic idea is simple:

> **A document that is more likely to be relevant should receive a higher ranking.**

Unlike the Boolean model, which gives a simple match/no-match result, the probabilistic model estimates **relevance probabilities** and ranks documents accordingly.

---

## 2. Definition

The **Probabilistic Retrieval Model** is a model in which documents are ranked according to the estimated probability that they are **relevant to a given query**.

For a document $D$ and query $Q$, the model tries to estimate:

$$
P(R=1\mid D,Q)
$$

where:

* $R=1$ means the document is relevant.
* $D$ is a document.
* $Q$ is the user's query.

Documents with higher probability are ranked higher.

---

# 3. Basic Principle

Suppose a user searches for:

**"machine learning"**

There are three documents:

| Document | Probability of Relevance |
| -------- | -----------------------: |
| D1       |                     0.90 |
| D2       |                     0.65 |
| D3       |                     0.30 |

The system ranks them:

$$
D1>D2>D3
$$

because D1 has the highest estimated probability of being relevant.

---

# 4. Probability Ranking Principle

The foundation of the model is the **Probability Ranking Principle (PRP)**.

It states that documents should be ranked in **decreasing order of their probability of relevance** to the query.

In simple terms:

$$
\boxed{\text{Higher relevance probability} \Rightarrow \text{Higher ranking}}
$$

This aims to maximize the effectiveness of retrieval for the user.

---

# 5. Binary Independence Model

A commonly discussed version of the probabilistic model is the **Binary Independence Model (BIM)**.

It assumes:

1. Terms are represented as **binary values**.
2. A term is either present or absent.
3. Terms are assumed to be statistically independent.
4. Documents can be divided into relevant and non-relevant sets.

For example:

| Term     | D1 |
| -------- | -: |
| machine  |  1 |
| learning |  1 |
| database |  0 |

Here:

* `1` → term is present
* `0` → term is absent

---

# 6. Relevance Estimation

Initially, the system may not know which documents are relevant.

It makes an initial estimate and retrieves documents.

The user can then provide **relevance feedback**, indicating which results are useful.

The system uses this information to improve its estimates.

The process is:

```text
Query
  ↓
Initial retrieval
  ↓
User examines results
  ↓
Relevance feedback
  ↓
Update relevance estimates
  ↓
Re-rank documents
```

---

# 7. Relevance Feedback

**Relevance feedback** is an important part of probabilistic retrieval.

Suppose the user searches:

**"information retrieval"**

The system initially returns:

```text
D1 → Relevant
D2 → Relevant
D3 → Not relevant
D4 → Relevant
```

The system learns which terms are associated with relevant documents and adjusts the ranking.

For example, if `indexing` frequently appears in relevant documents, documents containing `indexing` may receive a higher score.

Thus:

$$
\text{Initial Query}
\rightarrow
\text{Results}
\rightarrow
\text{Feedback}
\rightarrow
\text{Improved Results}
$$

---

# 8. BM25 and Probabilistic Retrieval

A very important practical ranking function derived from the probabilistic approach is **BM25**.

BM25 considers factors such as:

* Term frequency
* Inverse document frequency
* Document length
* Query terms

A common form is:

$$
Score(D,Q)=
\sum_{t\in Q}
IDF(t)
\frac{f(t,D)(k_1+1)}
{f(t,D)+k_1\left(1-b+b\frac{|D|}{avgdl}\right)}
$$

where:

* $f(t,D)$ = frequency of term $t$ in document $D$
* $|D|$ = length of document $D$
* $avgdl$ = average document length
* $k_1$ and $b$ = tuning parameters
* $IDF(t)$ = inverse document frequency

BM25 is widely used as a strong traditional baseline for search and document ranking.

---

# 9. Advantages

1. **Ranks documents by estimated relevance.**
2. Handles **partial matching**.
3. Can incorporate **relevance feedback**.
4. Provides a theoretical basis for document ranking.
5. BM25 provides effective ranking using term frequency and document-length normalization.
6. More flexible than simple Boolean retrieval.

---

# 10. Limitations

1. Estimating relevance probabilities can be difficult.
2. Initial relevance information may be unavailable.
3. Some probabilistic models make simplifying assumptions about term independence.
4. Performance depends on the quality of probability estimation.
5. The mathematical model can be more complex than Boolean retrieval.

---

# 11. Comparison with Other Retrieval Models

| Feature            | Boolean Model    | Vector Space Model   | Probabilistic Model      |
| ------------------ | ---------------- | -------------------- | ------------------------ |
| Basic idea         | Boolean matching | Vector similarity    | Probability of relevance |
| Output             | Match / no match | Similarity score     | Relevance score          |
| Ranking            | Usually no       | Yes                  | Yes                      |
| Common technique   | AND, OR, NOT     | TF-IDF + cosine      | BM25                     |
| Relevance feedback | Limited          | Possible             | Important                |

# 12. Example

Suppose the query is:

**"data mining"**

The system evaluates three documents:

| Document | Estimated Relevance |
| -------- | ------------------: |
| D1       |                0.85 |
| D2       |                0.60 |
| D3       |                0.25 |

The ranking becomes:

$$
D1>D2>D3
$$

If the user marks D1 as relevant, the system can use this feedback to improve the probability estimates and potentially change the ranking for the next retrieval.

---

# 13. Conclusion

The **Probabilistic Retrieval Model** ranks documents according to their estimated **probability of relevance** to a query.

Its central principle is:

$$
\boxed{
P(\text{relevant}\mid D,Q)
\rightarrow
\text{rank documents by decreasing probability}
}
$$

The model introduced an important idea in Information Retrieval: **search should not simply determine whether a document matches; it should estimate how likely that document is to be relevant.**

### Exam memory trick

**Probabilistic Model → Estimate relevance → Rank by probability → Use feedback → BM25 is the famous practical model.**
