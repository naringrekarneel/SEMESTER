# 6. Vector Space Model with Cosine Similarity

## 1. Introduction

The **Vector Space Model (VSM)** is an Information Retrieval model that represents **documents and queries as vectors** in a multidimensional space.

Unlike the Boolean Retrieval Model, which gives only **match or no-match**, the Vector Space Model calculates a **similarity score** between a query and each document.

The documents can then be **ranked according to relevance**.

---

## 2. Definition

The **Vector Space Model** represents each document and query as a vector of term weights, usually using **TF-IDF**.

For example, if the vocabulary is:

```text
information, retrieval, system
```

a document can be represented as:

$$
D = (w_1,w_2,w_3)
$$

where each $w_i$ represents the weight of a term.

---

## 3. Basic Idea

Suppose we have three terms:

```text
information
retrieval
system
```

and a document has the following weights:

$$
D_1=(0.8,0.6,0.2)
$$

A query might be:

$$
Q=(0.7,0.5,0)
$$

So both the document and query are represented as vectors.

The similarity between them can be measured using the **angle between the vectors**.

# 4. Cosine Similarity

**Cosine similarity** measures the similarity between two vectors based on the cosine of the angle between them.

The formula is:

$$
\boxed{
\cos(\theta)=
\frac{D\cdot Q}
{|D||Q|}
}
$$

where:

* $D$ = document vector
* $Q$ = query vector
* $D\cdot Q$ = dot product
* $|D|$ = magnitude of document vector
* $|Q|$ = magnitude of query vector

---

# 5. Numerical Example

Consider two terms:

**information, retrieval**

Suppose the query vector is:

$$
Q=(1,1)
$$

and a document vector is:

$$
D=(2,1)
$$

### Step 1: Calculate the dot product

$$
D\cdot Q=(2\times1)+(1\times1)
$$

$$
=2+1=3
$$

### Step 2: Calculate magnitude of D

$$
|D|=\sqrt{2^2+1^2}
$$

$$
=\sqrt{5}
$$

### Step 3: Calculate magnitude of Q

$$
|Q|=\sqrt{1^2+1^2}
$$

$$
=\sqrt{2}
$$

### Step 4: Calculate cosine similarity

$$
\cos(\theta)=
\frac{3}{\sqrt{5}\sqrt{2}}
$$

$$
=\frac{3}{\sqrt{10}}
$$

$$
\approx 0.949
$$

Therefore:

$$
\boxed{\text{Cosine Similarity} \approx 0.949}
$$

A value close to **1** means the document is highly similar to the query.

---

# 6. Interpretation of Cosine Similarity

For typical non-negative TF-IDF vectors:

| Cosine Value | Meaning                                    |
| -----------: | ------------------------------------------ |
|            1 | Identical direction / very high similarity |
|   Close to 1 | Highly similar                             |
|   Close to 0 | Very little similarity                     |
|            0 | No shared weighted terms                   |

The important idea is:

> **Smaller angle → Higher similarity**

and

> **Larger angle → Lower similarity**

---

# 7. Role of TF-IDF

In practice, VSM generally uses **TF-IDF weights** instead of simply counting terms.

TF-IDF gives higher importance to terms that:

* Occur frequently in a particular document
* Occur in relatively few documents in the collection

A common TF-IDF formula is:

$$
TFIDF(t,d)=TF(t,d)\times IDF(t)
$$

where:

$$
IDF(t)=\log\left(\frac{N}{DF(t)}\right)
$$

Thus, the document and query vectors contain **weighted terms**.

---

# 8. Ranking Documents

Suppose a query is:

**"information retrieval"**

and the system calculates:

| Document | Cosine Similarity |
| -------- | ----------------: |
| D1       |              0.95 |
| D2       |              0.72 |
| D3       |              0.41 |
| D4       |              0.15 |

The system ranks them:

$$
D1>D2>D3>D4
$$

Therefore, **D1 is considered the most relevant document**.

This ranking capability is one of the biggest advantages of VSM over the basic Boolean model.

---

# 9. Advantages

1. **Ranks documents** according to similarity.
2. Provides a **degree of relevance**, rather than only yes/no matching.
3. Works well with **TF-IDF weighting**.
4. Simple mathematical representation.
5. Cosine similarity reduces the effect of different document lengths.
6. Allows partial matching between queries and documents.

---

# 10. Limitations

1. **Bag-of-words limitation:** Word order is generally ignored.
2. **Synonymy:** Different words with similar meanings may not be recognized as equivalent.
3. **Polysemy:** The same word can have different meanings.
4. Producing and storing large vectors can be computationally expensive.
5. Basic VSM does not understand the deeper semantic meaning of words.

---

# 11. Boolean Model vs Vector Space Model

| Feature        | Boolean Model         | Vector Space Model   |
| -------------- | --------------------- | -------------------- |
| Representation | Boolean values        | Numerical vectors    |
| Matching       | Exact                 | Partial              |
| Ranking        | Usually no            | Yes                  |
| Similarity     | Boolean logic         | Cosine similarity    |
| Term weights   | Usually absent        | TF-IDF commonly used |
| Output         | Matching/non-matching | Ranked documents     |
| Flexibility    | Lower                 | Higher               |

---

# 12. Conclusion

The **Vector Space Model** represents documents and queries as vectors in a multidimensional space. **Cosine similarity** is then used to measure how closely a document vector matches a query vector.

The key formula to remember is:

$$
\boxed{
\text{Cosine Similarity}=
\frac{D\cdot Q}
{|D||Q|}
}
$$

The higher the cosine similarity, the more relevant the document is likely to be.

### Exam memory trick

**VSM → Documents become vectors → TF-IDF gives weights → Cosine measures similarity → Documents are ranked.**
