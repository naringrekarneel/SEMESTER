# 1. Inverted Index — 10 Marks

## 1. Introduction

An **Inverted Index** is a fundamental data structure used in **Information Retrieval (IR) systems** to efficiently search and retrieve documents.

Instead of storing information **document-wise**, an inverted index stores information **term-wise**. It maintains a list of all documents in which each term occurs.

It is called **"inverted"** because it reverses the normal relationship:

**Document → Words**

into:

**Word/Term → Documents**

---

## 2. Definition

An **inverted index** is a data structure that maps each unique term in a collection of documents to a list of documents, and optionally the positions, in which that term appears.

The main components are:

* **Dictionary / Vocabulary:** Contains all unique terms.
* **Postings List:** For each term, stores the list of documents containing that term.
* **Document Frequency:** Number of documents containing the term.
* **Positions:** Optional information showing where the term occurs in each document.

---

## 3. Example

Consider the following three documents:

| Document | Content                        |
| -------- | ------------------------------ |
| D1       | `information retrieval system` |
| D2       | `information search system`    |
| D3       | `retrieval search engine`      |

### Step 1: Identify unique terms

The vocabulary is:

`information, retrieval, system, search, engine`

### Step 2: Create the inverted index

| Term        | Postings List |
| ----------- | ------------- |
| information | D1, D2        |
| retrieval   | D1, D3        |
| system      | D1, D2        |
| search      | D2, D3        |
| engine      | D3            |

This is the **inverted index**.

For example:

**retrieval → D1, D3**

means that the word *retrieval* occurs in documents D1 and D3.

---

## 4. How Inverted Index Works

The construction and searching process can be explained in the following steps:

### Step 1: Document Collection

The IR system collects a set of documents.

Example:

`D1, D2, D3`

### Step 2: Text Processing

Each document is processed using techniques such as:

* Tokenization
* Case folding
* Stop-word removal
* Stemming or lemmatization

For example:

`"The Information Retrieval System"`

may be converted into:

`information retrieval system`

### Step 3: Term Identification

Unique terms are extracted from the processed documents.

### Step 4: Create Postings Lists

For every term, the system records the documents containing that term.

Example:

`search → D2, D3`

### Step 5: Query Processing

When a user searches for a term, the system directly looks up that term in the index.

For example, query:

`search`

The index returns:

`D2, D3`

Thus, the system does not need to scan every document.

---

## 5. Boolean Query Example

Suppose the user searches:

**information AND system**

From the inverted index:

* information → D1, D2
* system → D1, D2

The intersection is:

`{D1, D2} ∩ {D1, D2} = {D1, D2}`

Therefore, the result is:

**D1 and D2**

For:

**information OR retrieval**

we take the union:

`{D1, D2} ∪ {D1, D3} = {D1, D2, D3}`

Therefore, all three documents are retrieved.

---

## 6. Positional Inverted Index

A more advanced inverted index can also store the **position of each term** within a document.

For example:

| Term        | Document and Position |
| ----------- | --------------------- |
| information | D1: 1, D2: 1          |
| retrieval   | D1: 2, D3: 1          |
| system      | D1: 3, D2: 3          |

This is called a **positional inverted index**.

It is useful for:

* Phrase queries
* Proximity searches
* Ranking
* Determining the distance between terms

For example, the phrase:

**"information retrieval"**

can be efficiently identified because the system knows that `information` occurs at position 1 and `retrieval` occurs at position 2 in D1.

---

## 7. Advantages

1. **Fast searching:** Directly finds documents containing a term.
2. **Efficient Boolean queries:** AND, OR, and NOT operations can be performed efficiently.
3. **Scalable:** Can handle very large document collections.
4. **Supports ranking:** Can be combined with TF-IDF and other ranking techniques.
5. **Supports phrase searching:** Positional indexes can identify exact phrases.
6. **Reduces search time:** The system does not need to scan every document.

---

## 8. Limitations

1. **Storage requirement:** Large collections can require significant storage.
2. **Index construction cost:** Creating the index for millions of documents can be computationally expensive.
3. **Updating the index:** Adding, deleting, or modifying documents requires index updates.
4. **Preprocessing dependency:** Poor tokenization or stemming can affect search quality.
5. **Complex implementation:** Large-scale indexes require efficient storage and compression techniques.

---

## 9. Applications

Inverted indexes are widely used in:

* Search engines
* Digital libraries
* Document retrieval systems
* E-commerce search
* Enterprise search systems
* Database search systems
* Text mining applications

For example, when a search engine receives a query such as **"machine learning"**, it can use its inverted index to quickly identify documents containing `machine` and `learning`.

---

## 10. Conclusion

An **inverted index is the backbone of many Information Retrieval systems**. It maps terms to the documents in which they occur, making searching much faster than scanning every document individually.

The basic structure is:

$$
\text{Term} \rightarrow \text{Postings List} \rightarrow \text{Documents}
$$

For example:

**retrieval → D1, D3**

Thus, inverted indexing provides an **efficient, scalable, and flexible mechanism for document searching and retrieval**.
