# 5. Boolean Retrieval Model

## 1. Introduction

The **Boolean Retrieval Model** is one of the simplest and most fundamental models used in **Information Retrieval (IR)**.

It represents documents using **Boolean logic** and retrieves documents based on whether they **contain or do not contain specific terms**.

The model uses three main Boolean operators:

* **AND**
* **OR**
* **NOT**

The result is generally **binary**: a document either satisfies the query or it does not.

---

## 2. Definition

The **Boolean Retrieval Model** is an Information Retrieval model in which a query is expressed as a **Boolean expression**, and documents are retrieved if they satisfy that expression.

For example:

```text
information AND retrieval
```

means that a document must contain **both** `information` and `retrieval`.

---

# 3. Basic Boolean Operators

## A. AND Operator

The **AND** operator requires **both terms** to be present.

Example:

```text
information AND retrieval
```

Suppose:

| Document | information | retrieval |
| -------- | ----------: | --------: |
| D1       |           1 |         1 |
| D2       |           1 |         0 |
| D3       |           0 |         1 |
| D4       |           1 |         1 |

The result is:

**D1, D4**

because both terms occur in these documents.

### Logic

$$
A \ AND \ B
$$

is true only when both $A$ and $B$ are true.

---

## B. OR Operator

The **OR** operator retrieves documents containing **at least one** of the terms.

Example:

```text
information OR retrieval
```

Using the same documents:

| Document | information | retrieval |
| -------- | ----------: | --------: |
| D1       |           1 |         1 |
| D2       |           1 |         0 |
| D3       |           0 |         1 |
| D4       |           1 |         1 |

The result is:

**D1, D2, D3, D4**

### Logic

$$
A \ OR \ B
$$

is true when either $A$, $B$, or both are true.

---

## C. NOT Operator

The **NOT** operator excludes documents containing a particular term.

Example:

```text
information AND NOT retrieval
```

From the table:

* D1 → contains both → excluded
* D2 → information but no retrieval → included
* D3 → no information → excluded
* D4 → contains both → excluded

Therefore, the result is:

**D2**

### Logic

$$
A \ AND \ NOT B
$$

means the document must contain $A$ but must not contain $B$.

---

# 4. Example Using an Inverted Index

Consider the following documents:

| Document | Content                        |
| -------- | ------------------------------ |
| D1       | `information retrieval system` |
| D2       | `information search system`    |
| D3       | `retrieval search engine`      |
| D4       | `information retrieval engine` |

The inverted index is:

| Term        | Documents  |
| ----------- | ---------- |
| information | D1, D2, D4 |
| retrieval   | D1, D3, D4 |
| search      | D2, D3     |
| system      | D1, D2     |
| engine      | D3, D4     |

---

## Query 1: `information AND retrieval`

We have:

```text
information → D1, D2, D4
retrieval   → D1, D3, D4
```

Take the intersection:

$$
{D1,D2,D4} \cap {D1,D3,D4}
$$

Result:

**D1, D4**

---

## Query 2: `information OR retrieval`

Take the union:

$$
{D1,D2,D4} \cup {D1,D3,D4}
$$

Result:

**D1, D2, D3, D4**

---

## Query 3: `information AND NOT retrieval`

Information:

```text
D1, D2, D4
```

Retrieval:

```text
D1, D3, D4
```

Remove documents containing retrieval:

**Result: D2**

---

# 5. Boolean Query Processing

Boolean queries are generally processed using the **inverted index**.

For example:

```text
information AND retrieval
```

The system obtains two postings lists:

```text
information → D1, D2, D4
retrieval   → D1, D3, D4
```

Then it performs an **intersection**:

```text
D1, D2, D4
      ∩
D1, D3, D4
      ↓
   D1, D4
```

Thus, the matching documents are retrieved efficiently.

---

# 6. Advantages

1. **Simple to understand and implement.**
2. Provides **precise control** over search conditions.
3. Efficient when combined with an inverted index.
4. Supports complex queries using AND, OR, and NOT.
5. Useful when users know exactly what they want.
6. Easy to explain and interpret because the results directly follow the query.

---

# 7. Limitations

1. **No ranking:** Traditional Boolean retrieval usually returns matching documents without ranking them by relevance.
2. **Exact matching:** A document either matches or does not match.
3. **Query formulation can be difficult** for ordinary users.
4. Small changes in a query can drastically change the result set.
5. It does not naturally consider **term frequency** or **term importance**.
6. It may return too many or too few documents.

---

# 8. Boolean Retrieval vs Ranked Retrieval

| Feature        | Boolean Model      | Ranked Model                                   |
| -------------- | ------------------ | ---------------------------------------------- |
| Matching       | Exact              | Degree of relevance                            |
| Output         | Matching documents | Ranked documents                               |
| Main operators | AND, OR, NOT       | Similarity/relevance scores                    |
| Ranking        | Usually absent     | Present                                        |
| Example        | `AI AND robotics`  | Documents ranked by relevance to `AI robotics` |
| User control   | High               | Lower but more flexible                        |

---

# 9. Applications

The Boolean Retrieval Model is useful in:

* Library search systems
* Legal information retrieval
* Database search
* Enterprise document search
* Digital libraries
* Academic information systems

For example, a legal researcher might search:

```text
contract AND fraud AND NOT employment
```

to find documents containing `contract` and `fraud` while excluding documents related to `employment`.

---

# 10. Conclusion

The **Boolean Retrieval Model** retrieves documents using logical operators such as **AND, OR, and NOT**.

Its basic principle is:

$$
\boxed{\text{Query} \rightarrow \text{Boolean Operation} \rightarrow \text{Matching Documents}}
$$

It is **simple, precise, and efficient**, especially when implemented using an inverted index. However, its major limitation is that traditional Boolean retrieval **does not rank documents according to their degree of relevance**.

### Quick exam memory trick

**AND → Both**

**OR → Any**

**NOT → Exclude**

That three-word rule is enough to reconstruct most Boolean-model examples in the exam.
