# 4. Role of Hashing in Indexing

## 1. Introduction

**Hashing** is a technique used to organize and retrieve data quickly by converting a key, such as a term or document identifier, into a specific location in a hash table.

In Information Retrieval, hashing can be used to make **index construction and term lookup faster**.

The basic idea is:

$$
\text{Term} \xrightarrow{\text{Hash Function}} \text{Index/Table Position}
$$

For example:

```text
"computer" → hash function → position 5
```

The system can then directly access position 5 instead of searching through the entire dictionary.

---

## 2. Definition

**Hashing** is a method of mapping a key to a fixed location in a hash table using a **hash function**.

A hash function can be represented as:

$$
h(k) = k \bmod m
$$

where:

* $k$ = key
* $m$ = size of the hash table
* $h(k)$ = resulting table position

---

## 3. Example

Suppose a hash table has **7 positions**, numbered 0 to 6.

Consider numerical keys:

`10, 17, 24, 31`

Using:

$$
h(k) = k \bmod 7
$$

we get:

| Key |  Calculation | Hash Position |
| --: | -----------: | ------------: |
|  10 | $10 \bmod 7$ |             3 |
|  17 | $17 \bmod 7$ |             3 |
|  24 | $24 \bmod 7$ |             3 |
|  31 | $31 \bmod 7$ |             3 |

All these keys map to position 3. This situation is called a **collision**.

# 4. Role of Hashing in Information Retrieval

### A. Fast Term Lookup

Hashing allows the system to quickly determine whether a term exists in the index.

For example:

```text
Query: retrieval
       ↓
Hash function
       ↓
Hash table position
       ↓
Retrieve term information
```

Instead of scanning the entire vocabulary, the system can directly access the expected location.

---

### B. Fast Dictionary Searching

An IR system may contain millions of unique terms.

A hash table can store:

```text
Term → Hash value → Dictionary entry
```

This makes operations such as:

* Search
* Insert
* Delete

very efficient on average.

---

### C. Faster Index Construction

During index construction, the system needs to determine whether a newly encountered term already exists in the dictionary.

For example:

```text
Document: "information retrieval"

information → Does it exist?
retrieval   → Does it exist?
```

Hashing can quickly perform these checks.

If the term does not exist, it can be inserted into the dictionary.

---

### D. Duplicate Detection

Hashing can help identify duplicate terms or records efficiently.

For example:

```text
computer
computer
computer
```

The system can quickly determine that the term already exists instead of creating multiple dictionary entries.

---

### E. Mapping Terms to Postings

A hash table can be used to map a term to its postings list:

```text
information → D1, D2
retrieval   → D1, D3
system      → D1, D2
```

The hash function determines where each term's entry is stored.

---

# 5. Collision Handling

A **collision** occurs when two different keys produce the same hash value.

For example:

$$
h(10)=3
$$

and

$$
h(17)=3
$$

Both keys want position 3.

Common collision-handling techniques are:

### 1. Separate Chaining

Multiple entries are stored in a list associated with the same hash position.

```text
Position 3 → 10 → 17 → 24
```

### 2. Linear Probing

If the calculated position is occupied, the system checks the next available position.

```text
Position 3 → occupied
Position 4 → occupied
Position 5 → empty
```

The new key is placed at position 5.

### 3. Quadratic Probing

Instead of checking positions sequentially, the system checks positions using increasing quadratic offsets.

---

# 6. Advantages of Hashing in Indexing

1. **Fast lookup** — Average lookup can be close to $O(1)$.
2. **Fast insertion** — New terms can be inserted efficiently.
3. **Efficient dictionary management** — Useful for large vocabularies.
4. **Fast duplicate detection** — Existing terms can be identified quickly.
5. **Simple implementation** — Hash tables are relatively easy to implement.
6. **Useful during index construction** — Helps maintain the term dictionary efficiently.

---

# 7. Limitations

1. **Collisions** can occur when different terms map to the same location.
2. A poor hash function can cause many collisions.
3. Hash tables require additional memory.
4. Hashing does not naturally maintain terms in sorted order.
5. Resizing may be required when the table becomes too full.
6. It is less suitable when operations require **ordered traversal** of terms.

---

# 8. Hashing vs Sequential Searching

| Feature                         | Hashing              | Sequential Search           |
| ------------------------------- | -------------------- | --------------------------- |
| Lookup                          | Very fast on average | Slow for large dictionaries |
| Average complexity              | $O(1)$               | $O(n)$                      |
| Data organization               | Hash table           | Sequential list             |
| Collision                       | Possible             | Not applicable              |
| Suitable for large dictionaries | Yes                  | Less suitable               |

---

## 9. Applications in IR

Hashing is commonly useful for:

* Term dictionary lookup
* Index construction
* Duplicate detection
* Dictionary management
* Caching
* Fast lookup of document/term information

---

## 10. Conclusion

Hashing plays an important role in indexing by providing **fast access to terms and their associated information**. A hash function converts a term into a table position, allowing the system to locate index entries efficiently.

The key idea to remember is:

$$
\boxed{\text{Term} \rightarrow \text{Hash Function} \rightarrow \text{Table Position} \rightarrow \text{Index Entry}}
$$

Thus, hashing improves the **speed and efficiency of index construction and searching**, although collision handling and additional memory requirements must be considered.
