# 8. Language Models for Information Retrieval

## 1. Introduction

A **Language Model (LM)** in Information Retrieval is a statistical model that estimates the probability of a sequence of words.

In IR, the **language modeling approach** treats each document as a language model and asks:

> **How likely is this document to generate the user's query?**

Documents that are more likely to generate the query are ranked higher.

---

## 2. Definition

A **Language Model for Information Retrieval** is a probabilistic model that estimates the probability of a query being generated by a document.

The basic idea is:

$$
\boxed{\text{Document} \rightarrow \text{Language Model} \rightarrow P(Q\mid D)}
$$

where:

* $Q$ = query
* $D$ = document
* $P(Q\mid D)$ = probability of generating query $Q$ from document $D$

A higher $P(Q\mid D)$ generally means the document is considered more relevant.

---

# 3. Basic Principle

Suppose the user searches:

**"machine learning"**

Consider two documents:

**D1:**
`machine learning algorithms are useful`

**D2:**
`football players and sports news`

D1 contains words strongly related to the query, so its language model will assign a much higher probability to generating `"machine learning"`.

Therefore:

$$
P(Q\mid D1)>P(Q\mid D2)
$$

and D1 receives a higher ranking.

---

# 4. Query Likelihood Model

The most common language-model approach in IR is the **Query Likelihood Model**.

The system calculates:

$$
P(Q\mid D)
$$

and ranks documents according to this probability.

If the query contains multiple terms:

$$
Q=(q_1,q_2,\ldots,q_n)
$$

then, under the **unigram language model** assumption:

$$
P(Q\mid D)
==========

\prod_{i=1}^{n}P(q_i\mid D)
$$

For a query containing:

```text
information retrieval
```

we estimate:

$$
P(Q\mid D)
==========

P(information\mid D)
\times
P(retrieval\mid D)
$$

---

# 5. Estimating Term Probability

The simplest way to estimate the probability of a term $t$ in document $D$ is:

$$
P(t\mid D)=\frac{tf(t,D)}{|D|}
$$

where:

* $tf(t,D)$ = number of times term $t$ occurs in document $D$
* $|D|$ = total number of terms in document $D$

### Example

Suppose:

**D1:** `data mining data analysis`

There are 4 terms.

The term `data` occurs 2 times.

Therefore:

$$
P(data\mid D1)=\frac{2}{4}=0.5
$$

So the document's language model assigns probability **0.5** to the word `data`.

---

# 6. The Zero-Probability Problem

A major problem occurs when a query term does not appear in a document.

Suppose:

```text
Query = "data mining"
```

and `mining` does not occur in D1.

Then:

$$
P(mining\mid D1)=0
$$

Since the query probability is calculated by multiplication:

$$
P(Q\mid D1)=P(data\mid D1)\times P(mining\mid D1)
$$

the entire probability becomes:

$$
P(Q\mid D1)=0
$$

Even though the document might still be somewhat relevant.

This is called the **zero-probability problem**.

---

# 7. Smoothing

To solve the zero-probability problem, **smoothing techniques** are used.

Smoothing gives a small non-zero probability to terms that do not appear in the document.

Common techniques include:

### 1. Laplace Smoothing

Adds a small count to every term.

### 2. Jelinek-Mercer Smoothing

Combines the document language model with the collection language model.

A common formula is:

$$
P(t\mid D) =
(1-\lambda)P(t\mid D)
+
\lambda P(t\mid C)
$$

where:

* $D$ = document
* $C$ = entire collection
* $\lambda$ = smoothing parameter

### 3. Dirichlet Smoothing

Another commonly used smoothing technique that adjusts document probabilities using collection statistics.

Smoothing is extremely important because it prevents unseen terms from receiving probability zero.

---

# 8. Log Probability

Multiplying many probabilities can result in extremely small numbers.

Therefore, systems commonly use **log probabilities**.

Instead of:

$$
P(Q\mid D)=\prod_{i=1}^{n}P(q_i\mid D)
$$

we use:

$$
\log P(Q\mid D)
===============

\sum_{i=1}^{n}\log P(q_i\mid D)
$$

This is computationally more stable and converts multiplication into addition.

---

# 9. Ranking Documents

Suppose the query is:

**"information retrieval"**

and the system calculates:

| Document | $P(Q\mid D)$ |
| -------- | -----------: |
| D1       |         0.80 |
| D2       |         0.55 |
| D3       |         0.20 |

The documents are ranked:

$$
D1>D2>D3
$$

because D1 has the highest probability of generating the query.

---

# 10. Types of Language Models

### A. Unigram Language Model

Considers each word independently.

$$
P(w_1,w_2,\ldots,w_n)
=====================

\prod_i P(w_i)
$$

This is commonly used in basic query-likelihood retrieval.

### B. Bigram Language Model

Considers pairs of consecutive words.

$$
P(w_1,w_2,\ldots,w_n)
\approx
\prod_iP(w_i\mid w_{i-1})
$$

For example:

`machine learning`

The probability of `learning` depends on the previous word `machine`.

### C. N-gram Language Model

Generalizes this idea to sequences of $n$ words.

These models can capture some word-order information, although traditional IR systems often use simpler unigram approaches.

---

# 11. Advantages

1. Provides a **probabilistic ranking mechanism**.
2. Naturally handles **partial matching**.
3. Can incorporate **collection statistics**.
4. Smoothing solves the zero-probability problem.
5. Provides a strong theoretical framework for retrieval.
6. Can be extended using n-gram and other language-model approaches.

---

# 12. Limitations

1. Basic models may assume word independence.
2. Word meaning and deeper semantics are not fully captured.
3. Probability estimation can be sensitive to document length.
4. Smoothing parameters need to be selected carefully.
5. Large-scale language models can require significant computational resources.

---

# 14. Conclusion

Language Models provide a probabilistic approach to Information Retrieval by treating each document as a model capable of **generating words**.

The key idea is:

$$
\boxed{
\text{Rank documents according to }P(Q\mid D)
}
$$

The typical process is:

**Query → Estimate query probability for each document → Apply smoothing → Rank documents**

The most important concept to remember for exams is:

> **A document is considered relevant when its language model assigns a high probability to the user's query.**
