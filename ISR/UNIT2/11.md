# 11. Dense Retrieval and Vector Similarity Search

## 1. Introduction

**Dense Retrieval** is a modern Information Retrieval technique that represents queries and documents as **dense numerical vectors called embeddings**.

Instead of relying only on exact keyword matching like traditional **TF-IDF or BM25**, dense retrieval captures the **semantic meaning** of text.

The system retrieves documents whose vector representations are most similar to the query vector.

### Simple idea

```text
User Query
    ↓
Embedding Model
    ↓
Query Vector
    ↓
Vector Similarity Search
    ↓
Most Similar Document Vectors
    ↓
Ranked Results
```

---

# 2. What is Dense Retrieval?

Dense retrieval represents text using a fixed-size vector.

For example:

```text
"How to learn Python?"
            ↓
      Embedding Model
            ↓
[0.21, -0.14, 0.87, 0.32, ...]
```

A document is represented in the same way.

The vectors are called **dense** because most dimensions contain numerical values rather than mostly zeros.

Mathematically:

$$
Q=f(q)
$$

and

$$
D=f(d)
$$

where:

* $q$ = query
* $d$ = document
* $f$ = embedding model
* $Q$ = query vector
* $D$ = document vector

---

# 3. What is Vector Similarity Search?

Once queries and documents are represented as vectors, the system needs to determine which vectors are closest to each other.

This is called **Vector Similarity Search**.

The most common similarity measures are:

1. **Cosine similarity**
2. **Dot product**
3. **Euclidean distance**

---

# 4. Cosine Similarity

Cosine similarity measures the angle between two vectors.

The formula is:

$$
\boxed{
\text{Cosine Similarity}(Q,D)
=============================

\frac{Q\cdot D}
{|Q||D|}
}
$$

A value closer to **1** generally means greater similarity for normalized/non-negative semantic embeddings.

### Example

Suppose:

$$
Q=(1,2)
$$

and:

$$
D=(2,4)
$$

The vectors point in exactly the same direction.

Therefore:

$$
\cos(\theta)=1
$$

So they have maximum cosine similarity.

# 5. Dense Retrieval Example

Suppose the user searches:

> **"How can I study programming?"**

Consider these documents:

**D1:**
`Python programming tutorial for beginners`

**D2:**
`Latest football match results`

**D3:**
`Guide to learning software development`

A dense retrieval system converts them into vectors.

| Item  | Vector Representation |
| ----- | --------------------- |
| Query | $Q$                   |
| D1    | $D_1$                 |
| D2    | $D_2$                 |
| D3    | $D_3$                 |

Suppose similarity scores are:

| Document | Similarity |
| -------- | ---------: |
| D1       |       0.91 |
| D3       |       0.87 |
| D2       |       0.18 |

The system returns:

$$
D1>D3>D2
$$

Notice that D3 can be retrieved even though it may not contain the exact word **"programming"** everywhere. The embedding captures related meaning.

# 6. Dense vs Sparse Retrieval

### Sparse Retrieval

Traditional approaches such as:

* Boolean Retrieval
* TF-IDF
* BM25

represent text using sparse term-based features.

Example:

```text
Query → "machine learning"

Matching terms → machine, learning
```

### Dense Retrieval

Uses semantic embeddings:

```text
Query → [0.12, 0.84, -0.21, ...]
Document → [0.15, 0.80, -0.18, ...]
```

The system compares the vectors.

---

# 7. Comparison

| Feature             | Sparse Retrieval      | Dense Retrieval           |
| ------------------- | --------------------- | ------------------------- |
| Representation      | Term-based            | Dense vectors             |
| Matching            | Keyword/lexical       | Semantic                  |
| Exact word matching | Strong                | Not required              |
| Synonyms            | Limited               | Better                    |
| Vector size         | Very large but sparse | Fixed-size and dense      |
| Example             | BM25                  | Embedding-based retrieval |
| Search method       | Inverted index        | Vector index              |

# 9. Vector Index

Searching every document vector one by one can be expensive when there are millions of documents.

Therefore, specialized **vector indexes** are used.

Common approaches include:

### A. Exact Search

Compares the query vector with every stored vector.

If there are $N$ documents, this can require approximately:

$$
O(N)
$$

similarity comparisons per query.

It provides exact nearest neighbors but can become expensive at large scale.

---

### B. Approximate Nearest Neighbor (ANN)

ANN methods search for vectors that are **very close** to the query without checking every vector.

They trade a small amount of recall for much faster search.

Popular approaches include:

* **HNSW**
* **IVF**
* **Product Quantization (PQ)**

These techniques make large-scale vector search practical.

---

# 10. HNSW

**Hierarchical Navigable Small World (HNSW)** is a popular approximate nearest-neighbor indexing technique.

It organizes vectors as a graph.

Conceptually:

```text
        A -------- B
       /            \
      C              D
       \            /
        E -------- F
```

The search navigates through nearby vectors to quickly reach vectors similar to the query.

### Advantages

* Fast search
* Good recall
* Works well for high-dimensional embeddings
* Widely used in vector search systems

---

# 11. Dense Retrieval Models

Dense retrieval commonly uses neural embedding models such as:

* **DPR (Dense Passage Retrieval)**
* **Sentence-BERT**
* Transformer-based embedding models
* Modern text embedding models

A typical **bi-encoder** architecture encodes the query and document separately:

$$
Q=f_q(q)
$$

$$
D=f_d(d)
$$

Then similarity is calculated:

$$
Score(Q,D)=Q\cdot D
$$

or using cosine similarity.

Because document vectors can be calculated beforehand, this approach is scalable.

---

# 12. Advantages of Dense Retrieval

### 1. Understands semantic meaning

It can retrieve documents with related meanings even without exact keyword matches.

### 2. Handles synonyms better

For example:

```text
"car repair"
```

can potentially retrieve:

```text
"automobile maintenance guide"
```

### 3. Good for natural-language queries

Users can ask questions in conversational language.

### 4. Useful for semantic search

It focuses on **meaning**, not just exact terms.

### 5. Works well with modern neural systems

Dense retrieval can be combined with neural rerankers such as BERT-based models.

---

# 13. Limitations

### 1. Computational cost

Generating embeddings and searching high-dimensional vectors can be expensive.

### 2. Requires embedding models

The quality of retrieval depends heavily on the quality of the embedding model.

### 3. Exact matching can be weaker

For queries involving exact identifiers, names, codes, or rare terms, lexical search may be better.

### 4. Approximate search may miss results

ANN methods trade some exactness for speed.

### 5. Storage requirements

Large collections require storing millions or billions of vectors.

---

# 14. Dense Retrieval + Traditional Retrieval

Modern search systems often combine both approaches.

```text
                 User Query
                     │
          ┌──────────┴──────────┐
          ▼                     ▼
    BM25 / Sparse          Dense Retrieval
       Search                   │
          │                     │
          └──────────┬──────────┘
                     ▼
              Candidate Results
                     │
                     ▼
              Neural Reranker
                     │
                     ▼
               Final Results
```

This is called **hybrid retrieval**.

The combination is powerful because:

* Sparse retrieval is excellent at **exact matching**.
* Dense retrieval is excellent at **semantic matching**.

# 16. Conclusion

Dense Retrieval represents queries and documents as **dense vectors**, while vector similarity search finds documents whose vectors are closest to the query vector.

The complete process is:

$$
\boxed{
\text{Text}
\rightarrow
\text{Embedding}
\rightarrow
\text{Vector}
\rightarrow
\text{Similarity Search}
\rightarrow
\text{Top-K Documents}
}
$$

The most important similarity measure is **cosine similarity**:

$$
\boxed{
\text{Similarity}(Q,D)
======================

\frac{Q\cdot D}
{|Q||D|}
}
$$

### Exam memory trick

**Dense Retrieval = Meaning → Embedding → Vector → Similarity → Top-K results**

And remember the big contrast:

> **BM25 asks: "Do these words match?"**
> **Dense retrieval asks: "Do these meanings match?"**
