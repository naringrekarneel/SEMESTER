# 10. BERT-based Neural Ranking Models

## 1. Introduction

**BERT-based Neural Ranking Models** use **BERT (Bidirectional Encoder Representations from Transformers)** to understand the semantic relationship between a user's query and a document.

Traditional ranking methods such as TF-IDF and BM25 mainly depend on **term matching**.

BERT-based models can understand **context and meaning**, so they can identify relevant documents even when the query and document use different but semantically related words.

### Simple idea

```text
Query + Document
       ↓
      BERT
       ↓
Semantic Representation
       ↓
Relevance Score
       ↓
Ranking
```

---

# 2. What is BERT?

**BERT** is a Transformer-based language model that learns contextual representations of words by considering the words surrounding them.

For example, the word **"bank"** has different meanings in:

* `I deposited money in the bank.`
* `We sat on the river bank.`

BERT uses the surrounding context to understand these different meanings.

This makes BERT useful for Information Retrieval.

---

# 3. BERT for Information Retrieval

In a BERT-based ranking system, the model receives:

* A **query**
* A **candidate document**

and predicts how relevant the document is to the query.

For example:

```text
Query:
"best machine learning course"

Document 1:
"Complete machine learning course with Python..."

Document 2:
"Latest football match results..."

        ↓

      BERT Ranker

        ↓

D1 → 0.94
D2 → 0.08
```

Therefore, D1 is ranked higher.

---

# 4. Architecture

A typical BERT-based ranking architecture is:

```text
                USER QUERY
                    │
                    ▼
           Candidate Retrieval
             (BM25 / Search)
                    │
                    ▼
          Candidate Documents
                    │
                    ▼
        ┌──────────────────────┐
        │   Query + Document   │
        │                      │
        │      BERT Model      │
        └──────────────────────┘
                    │
                    ▼
          Contextual Embedding
                    │
                    ▼
          Classification / Score
                    │
                    ▼
           Relevance Score
                    │
                    ▼
             Final Ranking
```

---

# 5. BERT Input Representation

BERT typically receives the query and document as a pair.

Conceptually:

```text
[CLS] Query [SEP] Document [SEP]
```

For example:

```text
[CLS] machine learning course [SEP]
best machine learning courses with Python [SEP]
```

### Important tokens

* **[CLS]** → special token whose representation can be used for classification/ranking.
* **[SEP]** → separates the query and document.

BERT uses:

* Token embeddings
* Position embeddings
* Segment/token-type information

to process the input.

---

# 6. Transformer and Self-Attention

BERT uses the **Transformer architecture**, particularly **self-attention**.

Self-attention allows the model to determine which words are important in relation to other words.

For example:

```text
Query:
"apple price"

Document:
"Apple released a new iPhone with a higher price."
```

BERT can use context to understand that **Apple** refers to the company rather than the fruit.

This contextual understanding is one of the major advantages of BERT over simple keyword matching.

---

# 7. BERT Ranking Process

### Step 1: User enters a query

Example:

```text
"deep learning applications"
```

### Step 2: Candidate retrieval

A traditional retrieval system such as BM25 retrieves a smaller set of candidate documents.

```text
1,000,000 documents
        ↓
BM25
        ↓
100 candidate documents
```

### Step 3: Query-document pairs

The system creates:

```text
Query + D1
Query + D2
Query + D3
...
```

### Step 4: BERT processing

Each pair is passed through BERT.

### Step 5: Relevance scoring

BERT predicts a relevance score.

Example:

| Document | BERT Score |
| -------- | ---------: |
| D1       |       0.95 |
| D2       |       0.82 |
| D3       |       0.41 |
| D4       |       0.12 |

### Step 6: Ranking

Documents are sorted:

$$
D1>D2>D3>D4
$$

---

# 8. Important BERT-based Ranking Models

## A. BERT Cross-Encoder

The query and document are given to BERT **together**:

$$
[CLS]\ Query\ [SEP]\ Document\ [SEP]
$$

BERT directly models interactions between query and document tokens.

### Advantage

Very accurate because it can capture detailed token-level interactions.

### Disadvantage

It is computationally expensive because BERT must process every query-document pair.

---

## B. BERT Bi-Encoder / Dual Encoder

The query and document are encoded **separately**.

```text
Query ──→ BERT ──→ Query Vector
                       │
                       │ Similarity
                       ▼
Document ─→ BERT ─→ Document Vector
```

The similarity between the vectors can be calculated using cosine similarity or another similarity function.

$$
Similarity(Q,D)=
\frac{Q\cdot D}
{|Q||D|}
$$

### Advantage

Much faster for large collections because document embeddings can be precomputed.

### Disadvantage

It may lose some fine-grained query-document interactions compared with a cross-encoder.

---

# 9. Cross-Encoder vs Bi-Encoder

| Feature                 | Cross-Encoder                             | Bi-Encoder            |
| ----------------------- | ----------------------------------------- | --------------------- |
| Query/document encoding | Together                                  | Separately            |
| Interaction             | Strong                                    | Limited               |
| Accuracy                | Usually higher                            | Usually lower         |
| Speed                   | Slower                                    | Faster                |
| Document embeddings     | Cannot generally precompute independently | Can precompute        |
| Suitable for            | Reranking                                 | Large-scale retrieval |

A common real-world architecture is therefore:

```text
Large Document Collection
          ↓
   BM25 / Dense Retrieval
          ↓
   Top 100 Candidates
          ↓
   BERT Cross-Encoder
          ↓
   Top 10 Results
```

This is called **two-stage retrieval/reranking**.

---

# 10. Training BERT Rankers

BERT ranking models can be trained using relevance data.

Example:

| Query            | Document | Relevance |
| ---------------- | -------- | --------: |
| machine learning | D1       |         3 |
| machine learning | D2       |         2 |
| machine learning | D3       |         0 |

The model learns to assign higher scores to more relevant documents.

Training approaches can include:

* Pointwise learning
* Pairwise learning
* Listwise learning

For pairwise training, the model may learn:

$$
Score(Q,D_{relevant})

>

Score(Q,D_{non-relevant})
$$

---

# 11. Advantages

1. **Understands contextual meaning.**
2. Captures relationships between query and document terms.
3. Handles synonyms better than simple keyword matching.
4. Can understand word meaning based on context.
5. Provides highly accurate reranking.
6. Can outperform traditional lexical ranking methods on many retrieval tasks.

---

# 12. Limitations

1. **High computational cost**, especially for cross-encoders.
2. Requires significant memory and GPU/accelerator resources for efficient inference.
3. Slower than traditional methods such as BM25.
4. Requires large training datasets for best performance.
5. BERT models can be difficult to interpret.
6. Processing every document with BERT is impractical for very large collections.

Therefore, BERT is commonly used as a **reranker rather than the first-stage retrieval system**.

---

# 13. Traditional Ranking vs BERT Ranking

| Feature               | TF-IDF / BM25  | BERT-based Ranking                     |
| --------------------- | -------------- | -------------------------------------- |
| Matching              | Mostly lexical | Semantic + contextual                  |
| Context understanding | Limited        | Strong                                 |
| Synonyms              | Limited        | Better                                 |
| Computational cost    | Low            | High                                   |
| Training required     | Usually no     | Usually yes                            |
| Ranking quality       | Good baseline  | Often higher                           |
| Large-scale retrieval | Very efficient | Usually used after candidate retrieval |

---

# 14. Applications

BERT-based neural ranking is used in:

* **Web search**
* **Question answering**
* **E-commerce search**
* **Document retrieval**
* **Enterprise search**
* **Academic search**
* **FAQ retrieval**
* **Semantic search**
* **Recommendation and content retrieval**

For example, a user might search:

**"How can I learn Python quickly?"**

A traditional system may focus on documents containing the exact words.

A BERT-based model can recognize that:

> `Python beginner tutorial`

may be highly relevant even though it does not contain the exact phrase **"learn Python quickly."**

---

# 15. Conclusion

**BERT-based Neural Ranking Models** use the contextual understanding of BERT to calculate the relevance between a query and documents.

The most important architecture is:

$$
\boxed{
\text{Query}
\rightarrow
\text{Candidate Retrieval}
\rightarrow
\text{BERT Reranking}
\rightarrow
\text{Relevance Score}
\rightarrow
\text{Final Ranking}
}
$$

The two important architectures are:

* **Cross-Encoder:** Query + document together → **high accuracy, slower**
* **Bi-Encoder:** Query and document separately → **faster, scalable**

### Exam memory trick

**BM25 finds candidates → BERT understands them → BERT scores them → final ranking.**

That is the core idea behind modern neural search.
