# 3. Index Compression Techniques

## 1. Introduction

**Index compression** is the process of reducing the amount of storage required to store an **inverted index** while maintaining efficient searching.

In a large Information Retrieval system, the index can become very large because millions of documents may contain billions of term occurrences.

Compression helps to:

* Reduce disk and memory usage
* Improve data transfer speed
* Increase cache efficiency
* Speed up query processing

---

## 2. Why Index Compression is Needed

Consider an inverted index:

```text
computer → D1, D5, D8, D12, D15, D20, ...
```

If the collection contains millions of documents, storing all document IDs directly requires a large amount of space.

Therefore, IR systems use compression techniques to represent the same information using fewer bits.

There are two major areas of compression:

1. **Dictionary compression**
2. **Postings-list compression**

---

# 3. Dictionary Compression

The **dictionary** contains all unique terms in the collection.

Example:

```text
computer
computing
computation
communication
```

Storing every term independently wastes space because many terms share common characters.

### Common techniques:

### A. String Compression

Terms can be stored using shared prefixes or other compact representations.

For example:

```text
compute
computer
computing
computation
```

Instead of storing the common part repeatedly, the system can store the shared prefix `comput`.

This reduces dictionary storage.

---

### B. Front Coding

**Front coding** is useful when dictionary terms are stored in sorted order.

Suppose we have:

```text
compute
computer
computing
computation
```

The common prefix can be stored once, while only the differing parts are stored separately.

Conceptually:

```text
comput + e
       + r
       + ing
       + ation
```

Thus, repeated characters are avoided.

---

# 4. Postings List Compression

A **postings list** contains document IDs associated with a term.

Example:

```text
retrieval → 10, 20, 30, 45, 60
```

Since document IDs are generally sorted, we can use **gap encoding**.

---

## A. Gap Encoding

Instead of storing the actual document IDs:

```text
10, 20, 30, 45, 60
```

we store the differences between consecutive document IDs:

```text
10, 10, 10, 15, 15
```

The first value remains unchanged.

### Formula

For document IDs:

$$
d_1,d_2,d_3,\ldots,d_n
$$

the gaps are:

$$
g_1=d_1
$$

and

$$
g_i=d_i-d_{i-1}
$$

for $i>1$.

Smaller numbers can then be represented using fewer bits.

---

# 5. Variable-Byte Encoding

**Variable-Byte (VB) encoding** represents integers using a variable number of bytes.

The basic idea is:

> **Small numbers use fewer bytes, while large numbers use more bytes.**

Since gap encoding produces many small numbers, VB encoding works particularly well with postings lists.

### Example

Suppose the gaps are:

```text
3, 2, 1, 7, 2
```

These are small numbers, so they can be stored compactly rather than allocating a fixed-size integer for each value.

### Advantages

* Simple to implement
* Fast encoding and decoding
* Good for postings lists
* Reduces storage requirements

---

# 6. Gamma Encoding

**Elias Gamma encoding** is a bit-level compression technique used for positive integers.

It is particularly effective when the numbers being encoded are small.

For an integer $x$, its binary representation is used along with information about its length.

For example:

```text
Number → Binary representation
1      → 1
2      → 10
3      → 11
4      → 100
```

Gamma coding generally gives shorter representations to smaller numbers.

### Advantages

* Good compression for small integers
* Useful for gap-encoded postings
* Can achieve better compression than fixed-length encoding

### Disadvantage

* Encoding and decoding are more computationally expensive than simpler methods such as Variable-Byte encoding.

---

# 7. Delta Encoding

**Delta encoding** stores the difference between consecutive values.

This is essentially the idea behind gap encoding.

For example:

```text
Document IDs:
100, 105, 110, 120
```

After delta/gap encoding:

```text
100, 5, 5, 10
```

The smaller values are easier to compress.

Delta encoding can also be applied to other index information, such as:

* Document IDs
* Term positions
* Frequency information

---

# 8. Comparison of Compression Techniques

| Technique              | Applied To         | Main Idea                     | Benefit                     |
| ---------------------- | ------------------ | ----------------------------- | --------------------------- |
| String Compression     | Dictionary         | Reduce repeated characters    | Saves dictionary space      |
| Front Coding           | Dictionary         | Store common prefixes once    | Efficient for similar terms |
| Gap Encoding           | Postings           | Store differences between IDs | Produces smaller numbers    |
| Variable-Byte Encoding | Postings           | Variable number of bytes      | Fast and simple             |
| Gamma Encoding         | Postings           | Bit-level integer encoding    | High compression            |
| Delta Encoding         | Postings/positions | Store differences             | Reduces integer size        |

---

# 9. Advantages of Index Compression

1. **Reduces storage space** required by the index.
2. **Improves memory utilization**.
3. **Reduces disk I/O** during searching.
4. **Improves query processing speed** because less data needs to be transferred.
5. Allows larger indexes to fit into available memory.
6. Makes large-scale search engines more efficient.

---

# 10. Conclusion

Index compression is an important technique in Information Retrieval for managing the huge size of inverted indexes.

The two major areas are:

$$
\text{Index Compression}
========================

\text{Dictionary Compression}
+
\text{Postings Compression}
$$

Important techniques include **front coding, gap encoding, Variable-Byte encoding, Gamma encoding, and delta encoding**.

### Exam shortcut

Remember:

**Dictionary → Front Coding**

**Postings → Gap/Delta → Variable-Byte/Gamma**

This chain is basically the whole topic in one glance.
