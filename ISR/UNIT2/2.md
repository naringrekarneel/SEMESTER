# 2. Positional Index and Comparison with Inverted Index

## 1. Introduction

A **Positional Index** is an extension of the basic **Inverted Index** used in Information Retrieval.

A normal inverted index tells us **which documents contain a term**, whereas a positional index additionally tells us **where the term occurs inside each document**.

This makes positional indexes useful for **phrase queries** and **proximity searches**.

---

## 2. Definition

A **Positional Index** is an index that stores:

* A term
* The documents containing that term
* The **positions** at which the term occurs in each document

Basic structure:

$$
\text{Term} \rightarrow (\text{Document ID}, \text{Positions})
$$

---

## 3. Example

Consider these documents:

| Document | Content                        |
| -------- | ------------------------------ |
| D1       | `information retrieval system` |
| D2       | `information search system`    |
| D3       | `retrieval information system` |

Assume positions start from 1.

### Positional Index

| Term        | Postings                  |
| ----------- | ------------------------- |
| information | D1: [1], D2: [1], D3: [2] |
| retrieval   | D1: [2], D3: [1]          |
| system      | D1: [3], D2: [3], D3: [3] |
| search      | D2: [2]                   |

For example:

**information → D1:[1], D2:[1], D3:[2]**

This means:

* `information` occurs at position 1 in D1
* `information` occurs at position 1 in D2
* `information` occurs at position 2 in D3

---

## 4. How Positional Index Works

### Step 1: Tokenization

The document is divided into individual terms.

Example:

`information retrieval system`

becomes:

`information | retrieval | system`

### Step 2: Assign Positions

Each term receives a position.

| Position | Term        |
| -------: | ----------- |
|        1 | information |
|        2 | retrieval   |
|        3 | system      |

### Step 3: Build the Index

The system stores the document ID and positions for every term.

Example:

`retrieval → D1:[2], D3:[1]`

### Step 4: Process the Query

For a phrase query:

**"information retrieval"**

the system checks whether `information` and `retrieval` occur at consecutive positions.

In D1:

* information → position 1
* retrieval → position 2

Therefore, the phrase occurs in **D1**.

In D3:

* retrieval → position 1
* information → position 2

The order is reversed, so the phrase **"information retrieval"** does not occur there.

---

# 5. Positional Index vs Inverted Index

| Feature               | Inverted Index                   | Positional Index                   |
| --------------------- | -------------------------------- | ---------------------------------- |
| Basic purpose         | Finds documents containing terms | Finds documents and term locations |
| Stores document IDs   | Yes                              | Yes                                |
| Stores term positions | Usually no                       | Yes                                |
| Phrase queries        | Limited/not directly supported   | Efficiently supported              |
| Proximity searches    | Limited                          | Supported                          |
| Storage requirement   | Lower                            | Higher                             |
| Search capability     | Basic term/Boolean retrieval     | More advanced retrieval            |
| Complexity            | Simpler                          | More complex                       |
| Example               | `retrieval → D1, D3`             | `retrieval → D1:[2], D3:[1]`       |

---

## 6. Example of the Difference

Suppose:

**D1:** `information retrieval system`

A normal inverted index stores:

`information → D1`

`retrieval → D1`

It tells us that both terms occur in D1, but **not where**.

A positional index stores:

`information → D1:[1]`

`retrieval → D1:[2]`

Therefore, it can determine that:

**information retrieval**

appears as a phrase in D1.

---

## 7. Advantages of Positional Index

1. **Supports phrase queries**
   Example: `"information retrieval"`

2. **Supports proximity searches**
   Finds terms appearing close to each other.

3. **Improves search accuracy**
   The order and distance of terms can be considered.

4. **Useful for ranking**
   Documents where query terms occur close together can receive higher scores.

5. **Supports advanced search operations**
   Such as phrase matching and NEAR queries.

---

## 8. Limitations

1. Requires **more storage** because positions are stored.
2. Index construction is more complex.
3. Updating the index can require additional processing.
4. Searching may require processing positional information.

---

## 9. Key Difference to Remember

The easiest way to remember it:

> **Inverted Index = WHERE is the word? → Document IDs**
> **Positional Index = WHERE exactly is the word? → Document IDs + Positions**

### Inverted Index

$$
\text{Term} \rightarrow \text{Documents}
$$

### Positional Index

$$
\text{Term} \rightarrow (\text{Documents} + \text{Positions})
$$

---

## 10. Conclusion

A **Positional Index is an enhanced form of an Inverted Index**. While an inverted index identifies the documents containing a term, a positional index also records the exact positions of terms within those documents.

Therefore, positional indexing provides better support for **phrase queries, proximity searches, and accurate information retrieval**, at the cost of **additional storage and processing**.
