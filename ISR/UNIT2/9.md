# 9. Learning to Rank (LTR)

## 1. Introduction

**Learning to Rank (LTR)** is a machine learning approach used in **Information Retrieval** to automatically learn how to **rank documents according to their relevance to a user's query**.

Traditional retrieval models such as TF-IDF, BM25, or Vector Space Model use predefined mathematical rules.

LTR instead **learns ranking rules from training data**.

### Simple idea

Suppose a user searches:

**"best laptop for gaming"**

The search engine may have hundreds of documents.

LTR learns to arrange them as:

$$
D_1 > D_2 > D_3 > D_4
$$

where $D_1$ is predicted to be the most relevant.

---

# 2. Definition

**Learning to Rank** is a supervised machine learning technique in which a model is trained using **queries, documents, features, and relevance judgments** to learn an optimal ranking function.

The basic idea is:

$$
\boxed{
\text{Query + Document Features}
\rightarrow
\text{LTR Model}
\rightarrow
\text{Relevance Score}
\rightarrow
\text{Ranked Results}
}
$$

---

# 3. Why LTR is Needed

Traditional retrieval methods may use a fixed formula.

For example, BM25 considers factors such as:

* Term frequency
* Inverse document frequency
* Document length

But modern search systems have many other signals, such as:

* Query-document similarity
* Click-through rate
* Freshness
* Page quality
* User behavior
* Popularity
* Semantic similarity

LTR can **learn how to combine these signals** to produce better rankings.

---

# 4. LTR Architecture

A typical Learning-to-Rank architecture is:

```text
                USER QUERY
                    │
                    ▼
            Query Processing
                    │
                    ▼
          Candidate Retrieval
                    │
                    ▼
        ┌──────────────────────┐
        │ Feature Extraction   │
        └──────────────────────┘
                    │
                    ▼
          ┌─────────────────┐
          │  LTR Model      │
          │ ML Algorithm    │
          └─────────────────┘
                    │
                    ▼
          Relevance Scores
                    │
                    ▼
             Ranking / Sort
                    │
                    ▼
            Ranked Documents
```

---

# 5. Components of LTR Architecture

## A. User Query

The process starts when the user submits a query.

Example:

```text
"machine learning course"
```

---

## B. Candidate Retrieval

The search system first retrieves a relatively small set of potentially relevant documents using methods such as:

* Inverted index
* BM25
* Keyword matching
* Vector search

For example:

```text
100,000,000 documents
        ↓
Candidate retrieval
        ↓
1,000 candidate documents
```

LTR usually does not need to rank the entire collection from scratch.

---

## C. Feature Extraction

For each query-document pair, the system calculates features.

Examples include:

### Text-based features

* TF-IDF score
* BM25 score
* Number of matching terms
* Phrase match

### Document-based features

* Document length
* Page quality
* Freshness
* Popularity

### User-based features

* Click-through rate
* Previous interaction
* User preferences

### Semantic features

* Embedding similarity
* Query-document semantic similarity

---

## D. LTR Model

The extracted features are given to a machine learning model.

Example:

```text
BM25 = 4.8
Term match = 0.9
Freshness = 0.7
Popularity = 0.8
Semantic similarity = 0.95
        ↓
     LTR Model
        ↓
Relevance Score = 0.91
```

The model learns how much importance should be given to each feature.

---

## E. Ranking

The model generates a relevance score for every candidate document.

For example:

| Document | Score |
| -------- | ----: |
| D1       |  0.95 |
| D2       |  0.81 |
| D3       |  0.63 |
| D4       |  0.41 |

The system sorts them:

$$
D1>D2>D3>D4
$$

---

# 6. Training Data

LTR requires training data containing **relevance judgments**.

For example:

| Query            | Document | Relevance |
| ---------------- | -------- | --------: |
| machine learning | D1       |         3 |
| machine learning | D2       |         2 |
| machine learning | D3       |         0 |
| machine learning | D4       |         1 |

A common relevance scale is:

* **0** → Not relevant
* **1** → Slightly relevant
* **2** → Relevant
* **3** → Highly relevant

The model learns from these examples.

---

# 7. Types of Learning to Rank

LTR approaches are commonly divided into **three categories**.

## A. Pointwise Approach

Each query-document pair is treated independently.

The model predicts a relevance score for each document.

Example:

```text
Query + D1 → 0.90
Query + D2 → 0.60
Query + D3 → 0.20
```

Then documents are sorted according to their scores.

### Examples

* Linear Regression
* Logistic Regression
* Regression-based models

---

## B. Pairwise Approach

The model learns by comparing **two documents at a time**.

For example:

```text
D1 is more relevant than D2
```

The model learns:

$$
Score(D1)>Score(D2)
$$

### Examples

* RankSVM
* RankNet

The goal is to correctly order document pairs.

---

## C. Listwise Approach

The model considers the **entire ranked list** during training.

Instead of looking at one document or one pair, it tries to optimize the quality of the complete ranking.

### Examples

* ListNet
* ListMLE
* Lambda-based ranking methods are also commonly associated with list-oriented ranking optimization.

Listwise approaches are particularly useful when evaluation metrics depend on the quality of the entire ranked list.

---

# 8. LTR Algorithms

Popular LTR algorithms include:

* RankSVM
* RankNet
* LambdaMART
* ListNet
* ListMLE
* Gradient-boosted decision-tree ranking methods

**LambdaMART** is especially important in practical search-ranking systems because it combines learning-to-rank ideas with boosted decision trees.

---

# 9. Evaluation of LTR

LTR systems are evaluated using ranking metrics.

### A. Precision@K

Measures how many of the top $K$ retrieved documents are relevant.

$$
Precision@K=
\frac{\text{Relevant documents in top }K}{K}
$$

### B. Mean Average Precision (MAP)

Measures average precision across multiple queries.

### C. NDCG

**Normalized Discounted Cumulative Gain (NDCG)** gives more importance to highly relevant documents appearing near the top.

This is especially useful when relevance has multiple levels such as:

`0, 1, 2, 3`.

---

# 10. Applications of LTR

### 1. Web Search

Search engines rank web pages based on query relevance and many other signals.

### 2. E-commerce Search

When users search:

**"wireless headphones"**

LTR can rank products using:

* Text relevance
* Product popularity
* Reviews
* Price
* User behavior

### 3. Recommendation Systems

LTR can rank:

* Movies
* Songs
* Products
* News articles

according to predicted user interest.

### 4. Job Search

For a query such as:

**"Python developer"**

LTR can rank job postings based on:

* Skill match
* Experience
* Location
* Job relevance

### 5. News Retrieval

Articles can be ranked using:

* Query relevance
* Freshness
* Popularity
* User engagement

### 6. Enterprise Search

Organizations can rank internal documents based on relevance, permissions, document quality, and other signals.

---

# 11. Advantages

1. **Learns ranking automatically** from data.
2. Can combine many different ranking features.
3. Often improves search quality compared with manually designed ranking rules.
4. Can adapt to user behavior and changing data.
5. Supports complex ranking decisions.
6. Can optimize for specific evaluation metrics.

---

# 12. Limitations

1. Requires **large amounts of quality training data**.
2. Relevance judgments can be expensive to obtain.
3. Training can be computationally expensive.
4. Poor or biased training data can produce poor rankings.
5. Models may be difficult to interpret.
6. Search behavior and data can change over time, requiring retraining.

---

# 13. Traditional Retrieval vs LTR

| Feature       | Traditional Retrieval    | Learning to Rank             |
| ------------- | ------------------------ | ---------------------------- |
| Ranking rules | Hand-designed            | Learned from data            |
| Features      | Usually limited          | Many features                |
| Learning      | No/limited               | Machine learning             |
| User behavior | Difficult to incorporate | Can be incorporated          |
| Adaptability  | Lower                    | Higher                       |
| Training data | Not necessarily required | Required                     |
| Examples      | TF-IDF, BM25             | RankNet, RankSVM, LambdaMART |

---

# 14. Conclusion

**Learning to Rank (LTR)** uses machine learning to learn how documents should be ordered for a given query.

The complete process can be remembered as:

$$
\boxed{
\text{Query}
\rightarrow
\text{Candidate Retrieval}
\rightarrow
\text{Feature Extraction}
\rightarrow
\text{LTR Model}
\rightarrow
\text{Relevance Score}
\rightarrow
\text{Ranked Results}
}
$$

LTR is widely used in **web search, e-commerce, recommendation systems, job search, news retrieval, and enterprise search**.

### Exam memory trick

**LTR = Features + Training Data + ML Model → Better Ranking**

And remember the three approaches:

**Pointwise → one document**

**Pairwise → two documents**

**Listwise → whole ranking list**
