# Complete Text Processing Pipeline Before Indexing

## 1. Introduction

Before documents are stored in an **Information Retrieval (IR) index**, their raw text must be cleaned and transformed into a standard representation.

This process is called the **text processing pipeline**.

The main purpose is to:

* Remove unnecessary information.
* Normalize text.
* Reduce the vocabulary size.
* Improve retrieval speed.
* Improve search accuracy.

### Complete Pipeline

```text
Raw Documents
      ↓
Text Extraction
      ↓
Tokenization
      ↓
Case Folding
      ↓
Stop-word Removal
      ↓
Normalization
      ↓
Stemming / Lemmatization
      ↓
Term Filtering
      ↓
Term Weighting
      ↓
Index Construction
```

---

# 2. Text Extraction

The first step is to extract the actual text from different types of documents.

Documents may be:

* HTML pages
* PDF files
* Word documents
* Emails
* Plain text files

For example:

```text
PDF / HTML / DOCX
       ↓
   Extract text
       ↓
"Machine Learning is useful..."
```

Unnecessary elements such as HTML tags, formatting information, and sometimes metadata may be removed.

---

# 3. Tokenization

**Tokenization** divides the text into smaller units called **tokens**, usually words.

Example:

```text
"Information Retrieval is important."

             ↓

Information | Retrieval | is | important
```

Each token can then be processed individually.

---

# 4. Case Folding

Case folding converts text into a common case, usually **lowercase**.

Example:

```text
Machine Learning
MACHINE LEARNING
machine learning

          ↓

machine learning
```

This prevents the system from treating the same word with different capitalization as separate terms.

---

# 5. Stop-word Removal

Very common words that provide little retrieval value can be removed.

Examples:

```text
the, is, a, an, of, in, on, and, to, for
```

Example:

```text
"The machine is used for learning."

              ↓

"machine used learning"
```

### Benefit

It reduces:

* Vocabulary size
* Index size
* Processing time

**Note:** Stop-word removal is optional and depends on the application because some common words can be meaningful.

---

# 6. Text Normalization

Normalization converts different forms of text into a consistent representation.

It may include:

* Removing unnecessary punctuation.
* Handling special characters.
* Normalizing whitespace.
* Handling numbers.
* Expanding or standardizing certain forms.

Example:

```text
"Machine-learning!!!"

          ↓

"machine learning"
```

The exact normalization rules depend on the IR system.

---

# 7. Stemming

**Stemming** reduces words to a common stem by removing prefixes or suffixes.

Example:

```text
connected
connecting
connection

       ↓

connect
```

Another example:

```text
studies → studi
```

The output does not necessarily have to be a valid English word.

### Purpose

It helps the system treat related word forms as similar terms.

---

# 8. Lemmatization

**Lemmatization** converts a word into its proper dictionary/base form.

Examples:

```text
studies  → study
running  → run
children → child
better   → good
```

Unlike stemming, lemmatization uses linguistic information and generally produces meaningful dictionary words.

---

# 9. Term Filtering

After normalization, unwanted or unhelpful terms may be filtered.

Examples:

* Very short terms.
* Extremely common terms.
* Noise.
* Invalid tokens.
* Certain numbers or symbols, depending on the application.

The objective is to keep **useful index terms**.

---

# 10. Term Weighting

After processing, terms can be assigned importance weights.

A common method is **TF-IDF**.

[
TF\text{-}IDF(t,d)
==================

TF(t,d)\times IDF(t)
]

This gives higher importance to terms that are frequent in a particular document but relatively rare across the collection.

Modern IR systems may use other ranking or representation methods, including learned embeddings.

---

# 11. Index Construction

Finally, the processed terms are stored in an **index**, commonly an **inverted index**.

Example:

```text
Term        Documents
────────────────────────
machine     D1, D3
learning    D1, D2, D3
python      D2, D4
retrieval   D1, D5
```

The index allows the IR system to quickly find documents containing a particular term instead of scanning every document.

---

# 12. Complete Example

Consider the raw document:

> **"The Students are Studying Machine Learning techniques!"**

### Step 1: Tokenization

```text
The | Students | are | Studying | Machine | Learning | techniques
```

### Step 2: Case Folding

```text
the | students | are | studying | machine | learning | techniques
```

### Step 3: Stop-word Removal

```text
students | studying | machine | learning | techniques
```

### Step 4: Stemming

Possible result:

```text
student | studi | machin | learn | techniqu
```

### OR Step 4: Lemmatization

```text
student | study | machine | learning | technique
```

### Step 5: Indexing

These processed terms are added to the inverted index:

```text
student   → D1
study     → D1
machine   → D1
learning  → D1
technique → D1
```

---

## Conclusion

**The text processing pipeline converts raw documents into clean, normalized, and searchable terms before indexing. It typically involves text extraction, tokenization, case folding, stop-word removal, normalization, stemming or lemmatization, term filtering, and term weighting. The resulting terms are stored in an inverted index, which enables fast and effective information retrieval.**

### Easy memory trick:

**Extract → Tokenize → Lowercase → Remove → Normalize → Stem/Lemma → Filter → Weight → Index**
