# Topic 6: Introduction to Classical Planning
**Module 2 | Important for exams/interviews**

## 1. What is Classical Planning?

**Definition (exam-ready):**
Classical planning is an AI technique in which an agent determines a sequence of actions that transforms an **initial state** into a **desired goal state**, assuming the environment is known, deterministic, and fully observable.

### ELI5

Imagine telling a robot:
> "Make me a cup of coffee."

The robot needs to figure out:
1. Get a cup.
2. Get coffee.
3. Add coffee to the cup.
4. Get water.
5. Heat the water.
6. Pour water into the cup.

The important idea is that the robot isn't simply reacting to each situation. It **plans a sequence of actions before or while executing the task**.

---

## 2. Basic Structure of a Planning Problem

A classical planning problem can be represented as:

$$P = (S, A, s_0, G)$$

Where:
* **$S$** = set of possible states
* **$A$** = set of actions
* **$s_0$** = initial state
* **$G$** = goal condition

The planner searches for an action sequence:
$$a_1, a_2, a_3, \dots, a_n$$

such that:
$$s_0 \xrightarrow{a_1} s_1 \xrightarrow{a_2} s_2 \xrightarrow{a_3} \dots \xrightarrow{a_n} s_G$$

The final state $s_G$ satisfies the goal.

---

## 3. Assumptions of Classical Planning

Classical planning usually makes several simplifying assumptions.

| Assumption | Meaning |
| :--- | :--- |
| **Fully observable** | Agent knows the current state |
| **Deterministic** | An action has a predictable result |
| **Static** | Environment doesn't unexpectedly change |
| **Discrete** | States and actions can be represented explicitly |
| **Known environment** | Agent knows relevant actions and their effects |
| **Single agent** | Usually one planning agent is considered |

### Example
Suppose a robot wants to move a box from Room A to Room B.

If the robot knows:
* where the box is,
* where the rooms are,
* which actions are possible,
* and what each action does,

then it can construct a plan.

---

## 4. Actions in Classical Planning

An action generally has two important parts:

### Preconditions
Conditions that must be true **before** an action can be performed.

### Effects
Changes produced **after** performing the action.

For example:
**Action: PickUp(Box)**

**Preconditions:**
* Robot is near the box.
* Robot's hand is empty.
* Box is on the floor.

**Effects:**
* Robot is holding the box.
* Box is no longer on the floor.

We can represent this as:
$$Action = Preconditions + Effects$$

---

## 5. Example: Robot Moving a Box

Suppose the initial state is:
```text
Robot = Room A
Box = Room A
Box = OnFloor
```

Goal:
```text
Box = Room B
```

Possible actions:

| Action | Preconditions | Effects |
| :--- | :--- | :--- |
| **PickUp(Box)** | Robot near Box, hand empty | Robot holds Box |
| **Move(A,B)** | Robot in A | Robot in B |
| **PutDown(Box)** | Robot holds Box | Box on floor |

A possible plan is:

$$PickUp(Box)$$
↓
$$Move(A,B)$$
↓
$$PutDown(Box)$$

Final state:
```text
Robot = Room B
Box = Room B
Box = OnFloor
```
Therefore, the goal is achieved.

## 6. Planning vs Search

This is a very important connection with the previous module.

| Search | Classical Planning |
| :--- | :--- |
| Searches through states | Searches for an action sequence |
| General problem-solving framework | Specifically represents actions, preconditions and effects |
| Often focuses on finding a path | Focuses on achieving a set of goals |
| BFS, DFS, UCS, A* | Forward planning, backward planning, STRIPS, etc. |

In fact, **planning can be viewed as a form of search**.
The planner searches through possible states generated by actions until it finds one satisfying the goal.

---

## 7. Forward Planning

Forward planning starts from the **initial state** and applies applicable actions until the goal is reached.

### Example
**Initial:**
```text
Robot = A
Box = A
```
**Goal:**
```text
Box = B
```

**Forward reasoning:**
```text
Initial State
     ↓
PickUp(Box)
     ↓
Move(A,B)
     ↓
PutDown(Box)
     ↓
Goal State
```

### Algorithm idea
1. Start with the initial state.
2. Find actions whose preconditions are satisfied.
3. Apply one action.
4. Generate a new state.
5. Repeat until the goal is satisfied.

Forward planning is intuitive because it follows the actual execution direction.

---

## 8. Backward Planning

Backward planning starts with the **goal** and asks:
> "What action could have produced this goal?"

Then it works backward until it reaches the initial state.

Suppose the goal is:
```text
Box = Room B
```

The planner asks:
**Which action can produce Box = Room B?**
Answer: `PutDown(Box)`

What must be true before PutDown?
```text
Robot is holding Box
Robot is in Room B
```

Now ask:
**Which action can make Robot hold Box?**
Answer: `PickUp(Box)`
And so on.

So backward planning produces:
```text
Goal
 ↓
PutDown(Box)
 ↓
Move(A,B)
 ↓
PickUp(Box)
 ↓
Initial State
```

The resulting execution order is reversed:
`PickUp(Box) → Move(A,B) → PutDown(Box)`

---

## 9. Forward vs Backward Planning

| Feature | Forward Planning | Backward Planning |
| :--- | :--- | :--- |
| **Starts from** | Initial state | Goal |
| **Direction** | Initial → Goal | Goal → Initial |
| **Reasoning** | "What can I do now?" | "What could achieve this?" |
| **Advantage** | Simple and intuitive | Can focus on goal-relevant actions |
| **Disadvantage** | May explore many irrelevant actions | Can become complex with many goals |

### Easy memory trick
* **Forward** = Where can I go?
* **Backward** = What do I need?

---

## 10. Classical Planning in Agentic AI

This is where the topic connects to **Agentic AI**.

Suppose you tell an AI agent:
> "Organize a meeting with my team."

A planning-based agent may decompose this into:
```text
Goal:
Organize meeting
        ↓
Find participants
        ↓
Check calendars
        ↓
Find common time
        ↓
Select meeting slot
        ↓
Create meeting
        ↓
Send invitations
```

Each step changes the agent's state.
For example:
```text
State 0: Meeting not planned
State 1: Participants identified
State 2: Availability collected
State 3: Time selected
State 4: Meeting created
State 5: Invitations sent
```

This is essentially **state-space planning applied to a real-world task**.

### Must remember
* Classical planning finds an **action sequence** that transforms an initial state into a goal state.
* It generally assumes the environment is **fully observable, deterministic, static and known**.
* Every action has **preconditions and effects**.
* **Forward planning:** initial → goal.
* **Backward planning:** goal → initial.
* Planning can be viewed as **search over possible states/actions**.
* Classical planning forms an important foundation for modern **AI agents and task planning**.
