# Prompt Engineering: CoT, System Prompts, and Few-Shot Learning — 10 Marks

## 1. Introduction

**Prompt Engineering** is the empirical science and design discipline of structuring, refining, and optimizing natural language inputs (prompts) delivered to Large Language Models (LLMs) to guide them toward accurate, logically consistent, and contextually relevant outputs **without altering the model's underlying weights**.

* **Mechanism:** Relies on **In-Context Learning (ICL)**, an emergent capability of Transformer decoders where the attention mechanism dynamically attends to instructions, constraints, and demonstration exemplars present within the active context window.
* **Core Value:** Dramatically improves reasoning accuracy, reduces hallucinations, formats structured outputs (e.g., JSON), and enforces domain-specific personas at zero fine-tuning cost.

### ELI5 Analogy
Imagine assigning an essay to an exceptionally intelligent student:
* **Vague Prompt:** *"Write about energy."* $\to$ The student produces a disorganized, generic essay covering physics, biology, and nutrition.
* **Engineered Prompt:** *"You are a renewable energy specialist. Write a 3-paragraph summary comparing Solar vs. Wind power for a 10-mark university exam. Provide definitions, efficiency percentages, and a comparison table."* $\to$ The student outputs an exact, high-scoring answer matching all requirements.

## 3. Core Strategy 1: Chain-of-Thought (CoT) Prompting

Introduced by Wei et al. (Google Brain, 2022), **Chain-of-Thought (CoT)** prompting encourages language models to decompose complex multi-step reasoning problems into intermediate, explicit logical steps before arriving at the final answer.

```text
STANDARD PROMPTING                         CHAIN-OF-THOUGHT (CoT) PROMPTING
┌──────────────────────────────────────┐   ┌──────────────────────────────────────────────┐
│ Q: Roger has 5 tennis balls. He buys │   │ Q: Roger has 5 tennis balls. He buys 2 cans  │
│ 2 cans of 3 balls. How many does he  │   │ of 3 balls. How many does he have now?       │
│ have now?                            │   │                                              │
│ A: The answer is 11.                 │   │ A: Roger started with 5 balls.               │
│                                      │   │ 2 cans of 3 balls each is 2 × 3 = 6 balls.   │
│ [Model jumps directly to answer;     │   │ 5 + 6 = 11 balls.                            │
│ fails on complex arithmetic! ❌]      │   │ The answer is 11.                            │
└──────────────────────────────────────┘   │                                              │
                                           │ [Model allocates reasoning tokens before     │
                                           │ committing to final answer! ✅]              │
                                           └──────────────────────────────────────────────┘
```

### Why CoT Works (Mathematical Perspective):
In standard autoregressive generation, the model predicts the answer token $y$ conditioned directly on the prompt: $P(y \mid x)$. If the problem requires complex symbolic manipulation, calculating $y$ in a single forward pass exceeds the model's compute depth.

By emitting intermediate reasoning tokens $z_1, z_2, \dots, z_k$, the model generates each step by attending to previous steps:

$$P(y, z_1, \dots, z_k \mid x) = \prod_{i=1}^{k} P(z_i \mid x, z_{<i}) \cdot P(y \mid x, z_1, \dots, z_k)$$

This effectively grants the Transformer **additional computation time** (proportional to the number of reasoning tokens) to execute intermediate calculations.

### Variants of CoT:
1. **Few-Shot CoT:** Providing 2–3 exemplar problems where the answers explicitly demonstrate step-by-step reasoning.
2. **Zero-Shot CoT (Kojima et al., 2022):** Appending the magic phrase:
   > *"Let's think step by step."*
   This simple phrase activates latent reasoning pathways in the base model without requiring manual demonstrations.

### Concrete Example:
* **Prompt:** *"A merchant buys 10 laptops at ₹40,000 each and sells 8 of them for ₹50,000 each, while the remaining 2 are sold at ₹35,000 each. What is the total profit percentage? Think step by step."*
* **CoT Output:**
  1. $\text{Total Cost Price} = 10 \times 40,000 = ₹400,000$.
  2. $\text{Selling Price for first 8} = 8 \times 50,000 = ₹400,000$.
  3. $\text{Selling Price for remaining 2} = 2 \times 35,000 = ₹70,000$.
  4. $\text{Total Selling Price} = 400,000 + 70,000 = ₹470,000$.
  5. $\text{Total Profit} = 470,000 - 400,000 = ₹70,000$.
  6. $\text{Profit Percentage} = \frac{70,000}{400,000} \times 100 = 17.5\%$.
  7. **Final Answer:** $17.5\%$.

## 4. Core Strategy 2: System Prompts (Metaprompting)

### Definition & Architecture
A **System Prompt** is a persistent, top-level instruction placed in the model's initialization block that establishes the model's **persona, operational guidelines, safety guardrails, tone, and response constraints**.

In modern conversational APIs (OpenAI, Anthropic), dialogues are structured across three distinct message roles:

```json
[
  {
    "role": "system",
    "content": "You are an expert Deep Learning Professor. Answer strictly using technical rigor, include LaTeX equations, and format responses for university exams."
  },
  {
    "role": "user",
    "content": "What is vanishing gradient?"
  },
  {
    "role": "assistant",
    "content": "The vanishing gradient problem occurs when..."
  }
]
```

### Key Functions of System Prompts:
1. **Persona & Tone Control:** Defines voice (e.g., academic tutor vs. concise code linter).
2. **Behavioral Guardrails:** Enforces refusal of malicious queries (e.g., *"Refuse to generate exploits; maintain ethical safety standards."*).
3. **Output Formatting Contracts:** Guarantees machine-readable responses (e.g., *"Respond ONLY in valid RFC 8259 JSON format. Do not include markdown ticks."*).
4. **Context Grounding:** Limits knowledge retrieval strictly to provided documents (e.g., *"Answer solely based on the text provided below. If unknown, state 'Information not found.'"*).

## 5. Core Strategy 3: Few-Shot Learning (In-Context Exemplars)

### Definition
**Few-Shot Learning** (Brown et al., GPT-3, 2020) provides the model with $K$ explicit demonstration pairs $(x_i, y_i)$ directly within the prompt before presenting the new, unsolved query $x_{\text{test}}$.

```text
Zero-Shot Prompting               One-Shot Prompting                Few-Shot Prompting (K ≥ 2)
┌───────────────────────────────┐ ┌───────────────────────────────┐ ┌───────────────────────────────┐
│ Input: "The battery dies fast"│ │ Input: "Great battery life"   │ │ Input: "Great battery life"   │
│ Sentiment: ?                  │ │ Output: Positive              │ │ Output: Positive              │
│                               │ │                               │ │ Input: "Screen cracked early" │
│ [Zero demonstrations]         │ │ Input: "The battery dies fast"│ │ Output: Negative              │
│                               │ │ Sentiment: ?                  │ │ Input: "The battery dies fast"│
│                               │ │ [1 demonstration]             │ │ Sentiment: ? [K=2 exemplars]  │
└───────────────────────────────┘ └───────────────────────────────┘ └───────────────────────────────┘
```

### Why Few-Shot Works:
* Activates the model's in-context pattern recognition: the Transformer uses self-attention to align features across the demonstration examples.
* Resolves output ambiguity without fine-tuning or modifying weights.
* Demonstrates exact formatting preferences far more reliably than descriptive instructions alone.

### Concrete Example (Entity Extraction):
```text
Extract technical skills from text:

Example 1:
Text: "Candidate has 5 years of experience in PyTorch and Docker."
Entities: ["PyTorch", "Docker"]

Example 2:
Text: "Proficient in Kubernetes, Go, and Redis clusters."
Entities: ["Kubernetes", "Go", "Redis"]

Task:
Text: "Designed scalable APIs using FastAPI, PostgreSQL, and AWS S3."
Entities: ["FastAPI", "PostgreSQL", "AWS S3"]
```

## 6. Comprehensive Comparison of the Three Strategies

| Comparison Dimension | Chain-of-Thought (CoT) | System Prompts | Few-Shot Learning |
| :--- | :--- | :--- | :--- |
| **Primary Objective** | Solve multi-step reasoning problems | Establish global persona & constraints | Demonstrate exact input-output mapping |
| **Operational Mechanism**| Emits intermediate reasoning tokens | Sets top-level role in system channel | Provides $K$ input-output pairs |
| **Token Cost / Overhead**| Moderate (additional output tokens) | Low (constant system prefix) | High (consumes prompt context window) |
| **Primary Domain** | Math, logic, debugging, symbolic problems | Conversational bots, API agents, safety | Classification, entity extraction, formatting |
| **Best Example Trigger** | *"Let's think step by step"* | *"You are a senior database architect..."*| `Input: ... -> Output: ...` (repeated $K$ times) |
| **Susceptibility** | Hallucinations in intermediate steps | System prompt jailbreaks / prompt leaks | Recency bias & label order sensitivity |

## 7. Auxiliary Prompting Strategies

1. **Role Prompting:** Instructing the model to adopt a specific persona (*"Act as a Linux kernel developer"*).
2. **Self-Consistency (Wang et al.):** Generates multiple diverse CoT reasoning paths (e.g., $N=5$) and selects the majority voting answer.
3. **ReAct (Reasoning + Acting):** Combines CoT reasoning with external API calls, database queries, or search engine lookups.
4. **Least-to-Most Prompting:** Decomposes a problem into sub-problems and solves them sequentially.

## 8. Real-World Applications

* **Automated Code Debugging:** CoT forces the LLM to trace variable values through loop iterations to locate edge-case bugs.
* **Customer Support Chatbots:** System prompts constrain tone, enforce brand identity, and define company policies.
* **Clinical Data Extraction:** Few-shot examples teach models how to extract ICD-10 medical codes from complex doctor notes.
* **Automated Grading & Tutoring:** CoT generates step-by-step answer keys and pinpoints student errors.

---

## 9. Conclusion

Prompt Engineering bridges user intent and Large Language Model capabilities without modifying model weights. While **System Prompts** govern the global persona and behavioral constraints, **Few-Shot Learning** demonstrates input-output patterns via in-context examples, and **Chain-of-Thought Prompting** unlocks complex multi-step reasoning by providing additional computational space for intermediate logical steps.
