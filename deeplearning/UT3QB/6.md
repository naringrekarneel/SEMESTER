# Complete Workflow of Mixed Precision Training (FP16/BF16 Combined with FP32) — 10 Marks

## 1. Introduction

**Mixed Precision Training** (Micikevicius et al., 2017) is an advanced deep learning optimization technique that combines lower-precision 16-bit floating-point formats (**FP16** or **BF16**) with standard 32-bit floating-point numbers (**FP32**) within the same training loop.

* **Motivation:** Traditional deep neural networks train strictly using single-precision (FP32), which requires substantial GPU memory bandwidth and computation time.
* **Core Philosophy:** Most neural network operations (convolutions, matrix multiplications) are resilient to lower precision, while critical accumulators (weight updates, loss calculations, reductions) require high dynamic range to prevent numerical instability.
* **Benefits:**
  1. **$2\times$ to $4\times$ Faster Compute:** Harnesses specialized tensor hardware (NVIDIA Tensor Cores).
  2. **$\approx 50\%$ GPU Memory Reduction:** Enables doubling mini-batch sizes or training substantially larger models.
  3. **Zero Loss in Convergence/Accuracy:** Matches baseline FP32 validation performance.

## 2. Floating-Point Formats: Bit-Level Comparison

A floating-point representation consists of three parts: **Sign bit ($S$)**, **Exponent ($E$)** (which dictates dynamic range), and **Mantissa / Fraction ($M$)** (which dictates numerical precision):

$$\text{Value} = (-1)^S \times 2^{E - \text{bias}} \times \left(1 + \frac{M}{2^m}\right)$$

```text
FP32 : [ S (1) |      Exponent (8 bits)      |            Mantissa / Fraction (23 bits)           ]
FP16 : [ S (1) |  Exponent (5)  |     Mantissa (10 bits)     ]
BF16 : [ S (1) |      Exponent (8 bits)      | Mantissa (7) ]
```

| Format | Total Bits | Exponent Bits | Mantissa Bits | Exponent Bias | Smallest Positive Normalized | Largest Representable | Dynamic Range Profile |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **FP32** | 32 | 8 | 23 | 127 | $\approx 1.18 \times 10^{-38}$ | $\approx 3.40 \times 10^{38}$ | Full reference baseline |
| **FP16** | 16 | 5 | 10 | 15 | $\approx 6.10 \times 10^{-5}$ | $\approx 65,504$ | Narrow range; prone to underflow/overflow |
| **BF16** | 16 | 8 | 7 | 127 | $\approx 1.18 \times 10^{-38}$ | $\approx 3.40 \times 10^{38}$ | **Same dynamic range as FP32**; zero scaling needed |

## 4. Step-by-Step Execution Stages

### Step 1: Maintain FP32 Master Weights
* A master copy of all network parameters is held permanently in **FP32**.
* **Why this is mandatory:** During optimization, weight updates $\Delta \theta = -\eta \nabla L$ are often tiny (e.g., $10^{-3} \times 10^{-4} = 10^{-7}$).
* In FP16, the smallest subnormal positive number is $\approx 5.96 \times 10^{-8}$, and numbers $< 2^{-24} \times \theta$ truncate directly to zero. Adding a tiny FP16 gradient to a relatively large FP16 weight results in **swamping (underflow loss)**:
  $$\theta_{\text{FP16}} + \Delta \theta_{\text{FP16}} = \theta_{\text{FP16}} \quad (\text{No update occurs!})$$
* Retaining FP32 master weights ensures infinitesimal updates accumulate accurately over thousands of steps.

### Step 2: Casting & Forward Propagation (FP16 / BF16)
* At the beginning of each mini-batch, the FP32 master weights are converted (downcasted) to 16-bit format:
  $$\theta_{16} = \operatorname{cast}_{\text{FP16}}(\theta_{\text{FP32}})$$
* Forward operations (Convolutions, Linear GEMMs, Attention projections) run entirely in 16-bit precision using hardware **Tensor Cores**, which execute $4\times 4$ or $16\times 16$ matrix multiplication in FP16/BF16 and accumulate internally into FP32 registers.
* Layer activations are cached in 16-bit memory, cutting memory storage by $50\%$.

### Step 3: Numerically Stable Loss Computation
* Certain sensitive operations (Softmax, Log-Sum-Exp, Batch Normalization, Cross-Entropy) are accumulated in **FP32** to prevent exponent overflow ($e^z > 65,504$ in FP16).
* Computes the scalar loss $L \in \mathbb{R}$.

### Step 4: Loss Scaling (Mandatory for FP16)
* In deep models, a large percentage of gradient values during backpropagation reside in the interval $[10^{-8}, 10^{-5}]$.
* In FP16, anything below $6.1 \times 10^{-5}$ underflows to absolute zero ($0.0$), causing early layers to stall.
* **Loss Scaling Solution:** Multiply the loss by a scaling factor $S$ (e.g., $S = 2^{15} = 32,768$) before backpropagation:
  $$L_{\text{scaled}} = S \cdot L$$
* By the chain rule, this scales all backpropagated gradients by the exact same constant:
  $$\nabla_\theta L_{\text{scaled}} = \nabla_\theta (S \cdot L) = S \cdot \nabla_\theta L$$
* This shifts the entire gradient distribution into the valid representable dynamic range of FP16.

> **Note on BF16:** Because **BF16 has an 8-bit exponent** (identical to FP32), its minimum positive number is $1.18 \times 10^{-38}$. Therefore, **BF16 does NOT require loss scaling**.

### Step 5: Backpropagation (FP16 / BF16)
* Gradients of activations and weights are computed backward through the network in 16-bit precision.
* The scaled weight gradients $g_{\text{scaled}}^{[l]}$ are cached in GPU memory.

### Step 6: Gradient Unscaling & Dynamic Loss Scaling Inspection
* Before the optimizer applies updates, the gradients are cast to FP32 and divided by the scaling factor:
  $$g = \frac{g_{\text{scaled}}}{S}$$
* **Dynamic Loss Scaling Algorithm:**
  1. Inspect the gradient vector for arithmetic overflow (`Inf`) or invalid math (`NaN`).
  2. **If `Inf` or `NaN` is detected:** The scale factor $S$ was too large. **Skip the optimizer step entirely** (discard batch update) and reduce the scale factor:
     $$S \leftarrow \frac{S}{2}, \quad \text{reset counter}$$
  3. **If all gradients are finite:** Apply the optimizer update. If no overflow occurs for $N$ consecutive steps (e.g., $N=2000$), safely increase the scale factor:
     $$S \leftarrow 2 \cdot S$$

### Step 7: FP32 Optimizer Update & Next Iteration
* The optimizer (SGD with momentum, AdamW) updates the **FP32 master parameters** using unscaled gradients:
  $$\theta_{\text{FP32}}^{(t+1)} = \theta_{\text{FP32}}^{(t)} - \eta \cdot \frac{m_t}{\sqrt{v_t} + \epsilon}$$
* The updated master parameters are converted back to FP16/BF16, and the cycle repeats.

## 5. Summary Table: FP16 vs. BF16 Mixed Precision

| Dimension | FP16 Mixed Precision | BF16 Mixed Precision |
| :--- | :--- | :--- |
| **Exponent Bits** | 5 bits | **8 bits (Same as FP32)** |
| **Mantissa Bits** | 10 bits | 7 bits |
| **Dynamic Range** | Narrow ($6.1 \times 10^{-5}$ to $65,504$) | Massive ($\approx 10^{-38}$ to $10^{38}$) |
| **Loss Scaling Required?**| **Yes (Mandatory)** to prevent underflow | **No (Not required)** |
| **Risk of Overflow / Underflow**| Very High | Near Zero |
| **Hardware Requirement** | NVIDIA Volta (V100), Turing (T4), Ampere | NVIDIA Ampere (A100), Hopper (H100), Google TPU v2+ |
| **Industry Standard** | Legacy default (2017–2020) | Modern LLM standard (LLaMA, GPT-4) |

## 6. Advantages and Limitations

### Advantages:
1. **Dramatic Speedups:** Delivers up to $2\times - 3\times$ speedups on compute-bound architectures (ConvNets, Large Language Models).
2. **Reduced Memory Footprint:** Activation tensors and weight buffers occupy half the memory, allowing batch size expansion.
3. **Bandwidth Efficiency:** 16-bit bus transactions double effective GPU memory throughput.
4. **Seamless Integration:** Supported natively in PyTorch (`torch.cuda.amp.autocast`) and TensorFlow (`tf.keras.mixed_precision`).

### Limitations:
1. **Requires Hardware Tensor Cores:** Legacy GPUs without native 16-bit ALU pipelines run mixed precision via software emulation, resulting in slowdowns.
2. **Optimizer Memory Overhead:** Retaining FP32 master weights plus 16-bit weights increases parameter storage slightly (compensated by smaller activations).
3. **Sensitive Hyperparameters with FP16:** Poorly calibrated initial loss scales cause frequent skipped optimizer steps.

---

## 7. Conclusion

Mixed Precision Training balances the high execution speed and low memory footprint of 16-bit floating-point formats with the mathematical stability of 32-bit arithmetic. By coupling **FP32 master weights**, **Tensor-Core-accelerated FP16/BF16 forward-backward passes**, and **Dynamic Loss Scaling**, modern deep learning practitioners train state-of-the-art vision and language architectures at double the speed with zero degradation in empirical accuracy.

## Quick Revision for Exams

* **Trio of Mixed Precision:**
  1. **FP32 Master Weights:** Protects small parameter updates from swamping/underflow.
  2. **16-bit Forward/Backward Pass:** Halves memory and boosts throughput using Tensor Cores.
  3. **Loss Scaling ($S$):** Multiplies loss by $S$, backprops safely, divides gradients by $S$ before update (mandatory for FP16; unnecessary for BF16).
* **FP16 vs BF16:** FP16 has 5 exp bits (needs loss scaling); BF16 has 8 exp bits (matches FP32 range, no loss scaling required).

### 🧠 One-line memory trick
> **Compute in 16 to save time and memory, scale the loss to protect tiny gradients, and update in 32 to lock in the weights!**
